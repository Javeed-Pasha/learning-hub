Docker Setup

Docker ComposeNotebook WalkthroughRepo-Local Demo

This page shows how to run the local Spark plus Iceberg demo that backs the working reference implementation. It uses the repository’s saved Docker Compose file, mounted DDL and Spark runtime folders, and the included notebook walkthrough.

💡

Important: this is the local execution setup for the repository demo. It is not a new architecture component. It is the runnable environment for the reference implementation already described in the architecture and implementation pages.

Compose File

Use docker-compose.learning-hub.yml from the repository root. That file already contains the needed mounts for warehouse, notebooks, DDL, and Spark runtime code.

Fastest Path

Start Docker Compose, open Jupyter on http://localhost:8888, and run notebooks/learning_hub_demo.ipynb.

What It Runs

The notebook resets old demo tables, creates metadata and staging tables, seeds two batches, runs the pipeline, and builds the gold serving table.

What It Uses

The demo uses ddl/, spark/, notebooks/, warehouse/, and data/ directly from the repository.

Setup Prerequisites

Before You Start

You only need a few things in place before starting the demo stack.

RequirementWhy It Matters
Docker Desktop or Docker EngineRequired to run the Spark, Iceberg REST, MinIO, and helper containers defined in the compose file.
Repository checked out locallyThe compose file mounts repo folders directly, so the demo expects the project files to exist on your machine.
Ports availableThe stack uses the ports already defined in docker-compose.learning-hub.yml, including Jupyter on 8888.
✅

No extra mount setup is needed: the repo already includes warehouse/ and data/ plus the saved compose file with the correct mounts.

Start Docker Compose

Repo Root Command

From the repository root, start the local demo stack with the saved compose file:

docker compose -f docker-compose.learning-hub.yml up -d

This brings up the services already wired into the repo setup:

ServicePurpose
spark-icebergSpark runtime plus Jupyter environment for the notebook walkthrough.
iceberg-restREST catalog service for the local Iceberg demo environment.
minioObject-store layer used by the local stack.
mcHelper service used in the compose stack.
⚠

If you changed the control-table schema previously: run the reset step from the notebook or apply ddl/demo_reset.sql before recreating metadata objects.

Open The Notebook

Preferred Run Path

Once the stack is up, open Jupyter at http://localhost:8888 and run:

notebooks/learning_hub_demo.ipynb

The notebook is the easiest way to run the demo end to end because it already sequences the setup steps correctly.

  1. Reset old demo tables if needed.
  2. Create demo.ctl, demo.staging, demo.bronze, demo.silver, and demo.gold.
  3. Seed batch 1 source data.
  4. Run the pipeline for customer, orders, product, invoice, and shipment.
  5. Seed batch 2 changed source data.
  6. Run the second batch.
  7. Build the final joined gold serving table.
  8. Inspect bronze, silver, and gold outputs.

Optional CLI Flow

When You Want To Run It Manually

If you prefer running the demo outside the notebook sequence, the manual flow is:

  1. Apply ddl/demo_metadata_framework.sql.
  2. Apply ddl/demo_staging_sources.sql.
  3. Apply ddl/demo_seed_batch_1001.sql.
  4. Run spark/run_pipeline.py.
  5. Apply ddl/demo_seed_batch_1002.sql.
  6. Run spark/run_pipeline.py again.
  7. Apply ddl/demo_sales_serving.sql.
🛠

Recommendation: use the notebook for first-run setup, then use the CLI flow later if you want to demonstrate individual runtime steps separately.

Setup Troubleshooting

Common Local Issues
IssueWhat To Check
Container paths missingUse the saved compose file directly instead of manually copying partial files or mounts.
Old schema conflictsRun ddl/demo_reset.sql before recreating metadata if you changed the control-table structure.
Notebook can’t find repo filesConfirm the stack was started from the repo root so the compose mounts resolve correctly.
Jupyter is up but demo notebook is missingCheck that notebooks/ is mounted and that notebooks/learning_hub_demo.ipynb exists in the repo.
