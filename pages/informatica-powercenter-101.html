How a Job Runs â€” Step by Step

1
Developer triggers the workflow
Manually from Workflow Manager, via scheduler, or using the pmcmd command-line tool.
2
Integration Service fetches metadata
Reads the mapping definition, session config, and connection details from the Repository Service.
3
DTM process is spawned
The Integration Service compiles the mapping into a DTM (Data Transformation Manager) process on a worker node.
4
DTM reads from source
Connects to the source using the configured connection object, executes the SQL query (or reads the file), and streams data into the pipeline buffer.
5

Each row passes through transformations in memory â€” filters remove rows, expressions derive new values, lookups enrich data, aggregators group results.
6
DTM writes to target
Commits transformed rows to the target DB or file. Commit intervals are configurable. Rejected rows are written to a reject file.
7
Session statistics written to repository
Rows read, written, rejected, and throughput are persisted. Workflow advances to the next task (or terminates/fails).

Performance Tuning Hierarchy

Always optimize in this order â€” the earlier stages have the greatest impact:

1
Push filters to the Source Qualifier SQL
Never extract rows you'll immediately filter in PowerCenter. A WHERE clause at the source saves network bandwidth and DTM memory. Best ROI of any optimization.
2
Enable Lookup Caching
A lookup without caching hits the DB for every input row. With static cache, the reference table is loaded into memory once. For a 10M-row pipeline with 1M lookup rows, this can be a 100Ã— speedup.
3
Use Source-side Joins in SQ (not Joiner transformation)
When both sources come from the same database, use a User Defined Join in the Source Qualifier. The DB engine is far better at joining than PowerCenter's in-memory Joiner.
4
Enable Bulk Load for large targets
Session â†’ Mapping tab â†’ Target Load Type = Bulk. Bypasses database redo logging for much faster insert throughput. Trade-off: no rollback capability per commit interval.
5
Add Partitioning for high-volume loads
Enable session partitioning and select the right partition type. For 500M+ row loads, 4â€“8 partitions with Hash Auto-Keys before aggregation can deliver near-linear speedup.
6
Tune DTM Buffer Size
Session â†’ Config Object â†’ DTM Buffer Size. Default is often 12MB â€” increase to 64â€“256MB for large pipelines. This is the memory available for the entire transformation pipeline in flight.
