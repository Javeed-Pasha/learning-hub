What is Tableau?

⏱ 4 min📌 Module 01🎓 Introduction

Tableau is the industry-leading data visualization and business intelligence platform. It lets you connect to data, create interactive visualizations, and share insights — all without writing code.

Why Tableau?

Visual Analytics

Drag-and-drop interface. Create charts, maps, and dashboards in minutes — not hours.

Connect Anywhere

Native connectors for SQL Server, PostgreSQL, Snowflake, BigQuery, Excel, CSV, APIs, and 80+ sources.

Self-Service BI

Business users can explore data independently. No need to wait for IT to build reports.

Powerful Calculations

Table calculations, LOD expressions, and statistical functions for deep analysis.

Connecting to Data

⏱ 4 min📌 Module 03🎓 Foundations

Connection Types

Live Connection

Queries the database in real-time. Always up-to-date. Can be slow for large datasets or complex queries.

Extract (.hyper)

Imports data into Tableau's Hyper engine (columnar, in-memory). Very fast. Schedule refreshes to stay current.

Common Data Sources

CategorySources
DatabasesSQL Server, PostgreSQL, MySQL, Oracle, Snowflake, BigQuery, Redshift, Databricks
FilesExcel, CSV, JSON, PDF, Spatial files (.shp, .kml)
CloudGoogle Sheets, Salesforce, Azure SQL, Amazon S3
OtherODBC, OData, Web Data Connector, REST API (via WDC)

Data Source Best Practices

💡

Use Extracts for dashboards — they're orders of magnitude faster than live connections. Use live only when you need real-time data (e.g., operational dashboards).

✅

Published Data Sources: Create and publish shared data sources to Tableau Server/Cloud. This ensures consistent definitions, reduces duplication, and simplifies governance.

Dimensions vs Measures

⏱ 4 min📌 Module 04🎓 Core Concepts

Understanding the difference between Dimensions and Measures is the foundation of everything in Tableau.

Dimensions (Qualitative)

Categorical fields that segment your data. They define the level of detail in your view. Examples: Region, Product Category, Customer Name, Date.

Measures (Quantitative)

Numeric fields that are aggregated. They answer "how much?" or "how many?". Examples: Sales, Quantity, Profit, Discount.

Blue vs Green

ColorTypeBehavior
BlueDiscreteCreates distinct, individual values (headers). Adds rows/columns to the view.
GreenContinuousCreates an axis with a range. Produces smooth gradients.
💡

Key Rule: Dimensions slice your data into categories. Measures give you the numbers for each category. Dragging a dimension to Rows/Columns creates headers; dragging a measure creates an axis.

Aggregation

Measures are always aggregated in Tableau. The default is SUM(), but you can change it:

AggregationUse
SUMTotal (default for most measures)
AVGAverage value
COUNTNumber of rows
COUNTDDistinct count
MIN / MAXExtremes
MEDIANMiddle value
ATTRReturns value if all are the same, else *

The Marks Card

The Marks Card is where you control how data points look. Every mark has these properties:

Color

Encode a dimension or measure with color. Dimensions = distinct palette; Measures = gradient.

Size

Scale marks by a measure. Larger values = bigger marks.

Shape

Different shapes per category (circle, square, triangle, etc.).

Label

Show values directly on marks. Can display any field.

Detail

Add granularity without visual encoding. Increases the level of detail.

Tooltip

Information shown on hover. Fully customizable with rich text and viz-in-tooltip.

Filters & Parameters

⏱ 5 min📌 Module 06🎓 Core Concepts

Filter Order of Operations

Tableau applies filters in a specific order. Understanding this is critical for correct results:

1
Extract Filters
Applied when creating an extract — limits rows imported
▼
2
Data Source Filters
Applied before any calculations — reduces data sent to Tableau
▼
3
Context Filters
Creates a temporary table — subsequent filters operate on this subset
▼
4
Dimension Filters → Measure Filters
Standard filters on the Filters shelf
▼
5
Table Calculation Filters
Applied last — hides marks but doesn't change the underlying calculation

Parameters

Parameters are user-input variables. Unlike filters, they don't directly filter data — they're used in calculations, reference lines, and dynamic controls.

Dynamic Measure Selector

Let users choose which measure to display (Sales, Profit, Quantity) using a parameter + calculated field.

Dynamic Top N

Parameter controls how many items to show (Top 5, Top 10, etc.). Combined with an index() or RANK().

Reference Lines

Use a parameter as a target/threshold line. Users can adjust the target value interactively.

Date Range

Start/End date parameters let users define custom date ranges beyond built-in filter options.

Calculated Fields

⏱ 5 min📌 Module 07🎓 Intermediate

Types of Calculations

Row-Level

Calculated per row before aggregation. Example: [Sales] - [Cost]

Aggregate

Uses aggregate functions. Example: SUM([Sales]) / SUM([Quantity])

Table Calculation

Computed after aggregation in the view. Example: Running total, percent of total.

Commonly Used Calculations

// Profit Ratio
SUM([Profit]) / SUM([Sales])

// Year-over-Year Growth
(SUM([Sales]) - LOOKUP(SUM([Sales]), -1))
  / ABS(LOOKUP(SUM([Sales]), -1))

// Dynamic Measure (with Parameter)
CASE [Measure Selector Parameter]
  WHEN "Sales"    THEN SUM([Sales])
  WHEN "Profit"   THEN SUM([Profit])
  WHEN "Quantity" THEN SUM([Quantity])
END

// IF / ELSE
IF [Profit] > 0 THEN "Profitable"
ELSEIF [Profit] = 0 THEN "Break Even"
ELSE "Loss"
END

// Date: Fiscal Year (starting April)
IF MONTH([Order Date]) >= 4
THEN YEAR([Order Date])
ELSE YEAR([Order Date]) - 1
END

String Functions

CONTAINS([Product Name], "Widget")  // Boolean check
LEFT([ID], 3)                       // First 3 characters
SPLIT([Full Name], " ", 1)           // First word
REPLACE([Code], "-", "")            // Remove dashes
TRIM(UPPER([Category]))              // Clean & uppercase

Table Calculations

⏱ 5 min📌 Module 08🎓 Intermediate

Table calculations are computed after the query returns results. They operate on the aggregated values already in the view — not on raw data.

Key Table Calculations

CalculationWhat It DoesExample
Running TotalCumulative sum across marksCumulative sales over months
Percent of TotalEach mark as % of all marksCategory share of total sales
DifferenceChange from previous markMonth-over-month change
Percent Difference% change from previous markGrowth rate
Moving AverageAverage of N surrounding values3-month moving average
RANKRank marks by a measureTop performing products
INDEXSequential number per markRow numbering

Addressing & Partitioning

Addressing (Compute Using)

The direction the calculation moves through. "Table across" = left to right. "Table down" = top to bottom.

Partitioning

Defines the scope/group for the calculation. The calc restarts at each partition boundary.

// Running Sum (across months, restarting per category)
RUNNING_SUM(SUM([Sales]))
// Addressing: Month (compute using)
// Partitioning: Category (restarts for each)

// Rank within each region
RANK(SUM([Sales]))
// Address across products, partition by region

LOD Expressions

⏱ 5 min📌 Module 09🎓 Advanced

Level of Detail (LOD) Expressions let you compute aggregations at a different granularity than what's in the view. They're computed at the data source level, before view-level filters.

LOD Types

FIXED

Compute at a specific level, ignoring the view's level of detail. Most commonly used.

INCLUDE

Add a dimension to the view's level of detail. Makes the calculation more granular.

EXCLUDE

Remove a dimension from the view's level of detail. Makes the calculation less granular.

Syntax & Examples

// FIXED: Total sales per customer (regardless of view)
{ FIXED [Customer ID] : SUM([Sales]) }

// FIXED: First purchase date per customer
{ FIXED [Customer ID] : MIN([Order Date]) }

// INCLUDE: Average sales per order per category
{ INCLUDE [Order ID] : SUM([Sales]) }
// Then wrap with AVG() to get avg order value per category

// EXCLUDE: Category sales as % of total
SUM([Sales]) / SUM({ EXCLUDE [Category] : SUM([Sales]) })

// Cohort analysis: assign each customer to their first order month
{ FIXED [Customer ID] : MIN(DATETRUNC('month', [Order Date])) }
⚠

Filter Interaction: FIXED LODs are computed before dimension filters (but after context filters). If you need a FIXED calculation to respect a filter, add that filter as a context filter.

Dashboards & Stories

⏱ 5 min📌 Module 10🎓 Advanced

Dashboard Design Principles

Purpose First

Start with the question: "What decision will this dashboard help make?" Every element should earn its place.

5-Second Rule

A user should understand the main insight within 5 seconds. Use clear titles, KPIs at the top, and visual hierarchy.

Limit to 3-4 Views

Don't overcrowd. Each view should answer one question. Use drill-down or navigation for more detail.

Consistent Formatting

Same colors, fonts, and layout patterns. Use the same color for the same measure across all views.

Dashboard Actions

Action TypeBehaviorUse Case
FilterClick a mark in one sheet to filter all other sheetsClick a bar to drill into detail
HighlightGray out non-related marksHover to spotlight a category
URLOpens a web pageLink to external documentation
Go to SheetNavigate to another dashboard/sheetBuild multi-page navigation
Set ActionUser selection populates a setDynamic "compare to" analysis
Parameter ActionClick to update a parameter valueClick a bar to set a reference target

Stories

A Story is a sequence of dashboards/sheets (story points) arranged to present a guided narrative. Think of it like a slide deck where each slide is an interactive Tableau view.

Performance & Best Practices

⏱ 4 min📌 Module 11🎓 Advanced

Performance Optimization

#StrategyImpact
1Use Extracts instead of live connections🔴 High
2Reduce row count at the source (filter early)🔴 High
3Hide unused fields from the data source🟡 Medium
4Use FIXED LODs over INCLUDE/EXCLUDE when possible🟡 Medium
5Limit the number of marks rendered (< 10K ideal)🔴 High
6Use context filters for dependent filters🟡 Medium
7Avoid blending — use joins or relationships instead🟡 Medium
8Use Performance Recorder (Help → Settings → Start Performance Recording)🟡 Diagnostics

Design Best Practices

Use Relationships (not Joins)

Tableau's relationship model (introduced in 2020.2) is smarter about aggregation and avoids unnecessary joins.

Publish Data Sources

Centralize data definitions on Server/Cloud. Consistent field names, calculations, and security.

Name Fields Clearly

Rename fields to business-friendly names. Use folders to organize. Add comments on complex calcs.

Dashboard Sizing

Use "Automatic" or "Range" sizing for responsive dashboards. Design for the smallest target screen first.

Tableau Server / Cloud

⏱ 4 min📌 Module 12🎓 Platform

Server vs Cloud

Tableau Server

Self-hosted on your infrastructure (Windows/Linux). Full control over hardware, security, and networking. You manage upgrades.

Tableau Cloud

Fully managed SaaS by Salesforce. No infrastructure to manage. Automatic updates. Per-user pricing.

Key Platform Features

FeatureDescription
PublishingPublish workbooks and data sources from Desktop to Server/Cloud
SchedulingSchedule extract refreshes (full or incremental) and subscription emails
Row-Level SecurityFilter data based on the logged-in user. Use USERNAME() or ISMEMBEROF()
Data GovernanceCertified data sources, data quality warnings, lineage tracking
PermissionsProject → Workbook → View level permissions. Lock or inherit from parent.
Prep ConductorSchedule Tableau Prep flows on Server (requires Data Management add-on)

Row-Level Security Example

// Calculated field for RLS
[Region Manager] = USERNAME()

// Or group-based
ISMEMBEROF("North America Team")
💡

Tip: Use published data sources with embedded RLS. This way, security is enforced regardless of which workbook connects to the data.

Date Functions

String Functions

CONTAINS([Name], "Corp")       // Boolean match
LEFT([Code], 3)                // First N chars
RIGHT([Code], 4)               // Last N chars
MID([Code], 2, 5)              // Substring
REPLACE([Text],"-","")         // Remove dashes
SPLIT([Name], " ", 1)          // First word
TRIM(UPPER([Code]))             // Clean + uppercase
LEN([Description])              // String length

LOD Quick Reference

{ FIXED [Dim] : AGG([Measure]) }     // Compute at Dim level
{ INCLUDE [Dim] : AGG([Measure]) }   // Add Dim to view LOD
{ EXCLUDE [Dim] : AGG([Measure]) }   // Remove Dim from view LOD
{ AGG([Measure]) }                    // Table-scoped (no dims)

Table Calculation Functions

RUNNING_SUM(SUM([Sales]))       // Cumulative total
RUNNING_AVG(SUM([Sales]))       // Cumulative average
WINDOW_SUM(SUM([Sales]))        // Sum across entire partition
WINDOW_AVG(SUM([Sales]),-2,0)  // 3-period moving avg
RANK(SUM([Sales]))               // Rank marks
INDEX()                         // Row number
FIRST()                         // Offset from first mark
LAST()                          // Offset from last mark
LOOKUP(SUM([Sales]), -1)        // Previous period value
ZN(LOOKUP(SUM([Sales]),-1))     // Previous (null-safe)

Logical Functions

IF [X] > 0 THEN "Pos" ELSE "Neg" END
IIF([X] > 0, "Pos", "Neg")               // Inline IF
CASE [Region]
  WHEN "East" THEN 1
  WHEN "West" THEN 2
  ELSE 3
END
ZN([Value])                              // Replace null with 0
IFNULL([Value], "N/A")                  // Replace null
