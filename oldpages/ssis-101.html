What is SSIS?

⏱ 4 min📌 Module 01🎓 Introduction

SQL Server Integration Services (SSIS) is Microsoft's enterprise ETL (Extract, Transform, Load) platform. It's part of the SQL Server stack and is used to build data integration and data transformation solutions.

Why SSIS?

Visual Development

Drag-and-drop design surface in Visual Studio / SSDT. Build complex ETL without writing code.

Microsoft Ecosystem

Native integration with SQL Server, Azure, Excel, SharePoint, and other Microsoft services.

Enterprise-Grade

Built-in logging, error handling, checkpoints, transactions, and parallel execution.

Extensible

Script tasks (C#/VB.NET), custom components, and third-party connectors extend functionality.

SSIS Projects & Packages

⏱ 4 min📌 Module 03🎓 Core Concepts

Project vs Package

ConceptDescription
Project (.ispac)A container that holds one or more packages, connection managers, parameters, and project-level configurations. This is what gets deployed.
Package (.dtsx)A single unit of work — one ETL workflow. Contains control flow, data flow(s), event handlers, and variables.
Connection ManagerDefines how to connect to data sources/destinations. Can be project-level (shared) or package-level.
ParameterValues passed into packages at runtime. Replaces old-style configurations. Can be project or package scoped.

Package Structure

Control Flow

The workflow orchestration layer. Tasks execute in order, with precedence constraints defining the flow (success/failure/completion).

Data Flow

The data pipeline layer. Sources extract data, transformations process it, and destinations load it. Runs inside a Data Flow Task.

Event Handlers

Code that runs when specific events occur (OnError, OnWarning, OnPreExecute, etc.).

Variables

Store values at runtime — used in expressions, SQL statements, and control flow logic. User or system scoped.

💡

Deployment Models: SSIS supports Project Deployment (to SSISDB catalog — recommended) and legacy Package Deployment (to file system or MSDB). Always prefer Project Deployment for new work.

Control Flow

⏱ 5 min📌 Module 04🎓 Core Concepts

The Control Flow is the backbone of an SSIS package. It defines what tasks run and in what order using tasks and precedence constraints.

Common Tasks

TaskPurpose
Data Flow TaskRuns a data pipeline (source → transform → destination). The most important task.
Execute SQL TaskRuns SQL statements — TRUNCATE, INSERT, stored procedures, DDL.
Script TaskRuns custom C# or VB.NET code for logic that can't be done visually.
File System TaskCopy, move, rename, or delete files and directories.
Send Mail TaskSends email notifications (success/failure alerts).
Execute Package TaskRuns another SSIS package — enables modular "parent-child" design.
For Loop / Foreach LoopIterates over items — files in a folder, rows in a table, etc.
Sequence ContainerGroups tasks together for organization, scoping variables, or applying transactions.

Precedence Constraints

Arrows between tasks that control execution flow based on the outcome of the previous task:

Success (Green)

Next task runs only if previous task succeeded.

Failure (Red)

Next task runs only if previous task failed. Used for error handling.

Completion (Blue)

Next task runs regardless of success or failure.

💡

Tip: Use Sequence Containers to group related tasks. You can apply a transaction scope to the container so all tasks inside either commit or rollback together.

Buffer-Based Pipeline

SSIS processes data in memory buffers, not row-by-row. The Data Flow Engine allocates buffers and moves data through the pipeline in chunks — this is what makes SSIS fast.

Buffer Size

Default 10 MB per buffer. Controlled by DefaultBufferMaxRows and DefaultBufferSize properties.

Execution Trees

The engine splits the data flow into execution trees. Synchronous transforms stay in the same tree; asynchronous ones create new trees.

Data Flow Transformations

⏱ 6 min📌 Module 06🎓 Core Concepts

Synchronous vs Asynchronous

Synchronous (Fast)

Output rows use the same buffer as input rows. No extra memory allocation. Examples: Derived Column, Conditional Split, Data Conversion, Lookup (cache mode).

Asynchronous (Slower)

Creates new buffers for output. Needs to read all input before producing output. Examples: Sort, Aggregate, Merge Join, Union All.

⚠

Performance Rule: Prefer synchronous transformations whenever possible. Avoid the Sort transform — sort data in the SQL source query instead.

Key Transformations

TransformTypeWhat It Does
Derived ColumnSyncCreates new columns or modifies existing using expressions. The most-used transform.
LookupSyncJoins data with a reference table. Used for SCD, key lookups, data enrichment.
Conditional SplitSyncRoutes rows to different outputs based on conditions (like a CASE/WHEN).
Data ConversionSyncConverts column data types (similar to CAST/CONVERT in SQL).
MulticastSyncSends identical copies of data to multiple outputs.
Union AllAsyncCombines rows from multiple inputs into a single output (like SQL UNION ALL).
Merge JoinAsyncPerforms INNER/LEFT/FULL joins. Requires sorted input.
AggregateAsyncPerforms GROUP BY operations — SUM, COUNT, AVG, etc.
SortAsyncSorts data. Expensive — prefer using ORDER BY in the source SQL.
Slowly Changing DimensionSyncWizard-based SCD Type 1/2 handling. Works but generates slow row-by-row operations.

Variables & Expressions

⏱ 4 min📌 Module 07🎓 Intermediate

Variables

Variables store values at runtime. They can be used in expressions, SQL queries, property overrides, and control flow logic.

ScopeDescription
PackageAvailable throughout the package.
ContainerAvailable within a Sequence Container, For Loop, or Foreach Loop.
TaskAvailable only within that specific task.

Common Data Types

TypeUse For
StringFile paths, SQL queries, connection strings
Int32Row counts, loop counters, flags
DateTimeTimestamps, date filters
BooleanFlags for conditional logic
ObjectStore result sets from Execute SQL Task

Expression Examples

// Dynamic file path with timestamp
@[User::FolderPath] + "\\Export_" +
  (DT_WSTR, 4)YEAR(GETDATE()) + ".csv"

// Yesterday's date for incremental load
(DT_DBTIMESTAMP)DATEADD("dd", -1, GETDATE())

// Conditional: if variable is empty, use default
LEN(@[User::ServerName]) > 0
  ? @[User::ServerName]
  : "localhost"
💡

Pro Tip: Use Expressions on Connection Manager properties to make packages environment-aware. Set the ConnectionString property via an expression that reads from a project parameter.

Event Handlers & Logging

⏱ 4 min📌 Module 08🎓 Intermediate

Event Handlers

Every package, container, and task raises events. You can attach tasks to these events to run custom logic.

EventWhen It FiresCommon Use
OnErrorWhen a task failsSend failure email, log to error table
OnWarningWarning raisedLog warnings for review
OnPreExecuteBefore task startsLog start times, set variables
OnPostExecuteAfter task completesLog end times, row counts
OnTaskFailedTask fails (package level)Cleanup, send alerts

Logging Options

SSIS Catalog Reports

Built-in reports in SSMS when using Project Deployment. Shows execution status, messages, performance stats.

Custom Logging Table

Create your own log table and insert records using Execute SQL Task in event handlers. Full control over what's logged.

SSIS Log Provider

Built-in logging to SQL Server, Windows Event Log, XML files, or text files. Configured per-package.

✅

Best Practice: Use the SSIS Catalog's built-in logging (set logging level to Performance or Verbose during development) and supplement with a custom audit table for business-level tracking.

Error Handling

⏱ 4 min📌 Module 09🎓 Intermediate

Control Flow Error Handling

Use Failure precedence constraints (red arrows) to define what happens when a task fails:

Failure Path

Connect a Send Mail Task or Execute SQL Task to the failure output to log errors and send alerts.

Checkpoints

Enable checkpoints on the package to restart from the last failed task instead of re-running everything.

Data Flow Error Handling

Every data flow component has an error output. You configure what happens when a row fails:

OptionBehavior
Fail ComponentDefault. The entire data flow fails on first error.
Redirect RowSend the bad row to an error output path. Best practice — log errors, don't stop the pipeline.
Ignore FailureSilently skip the error. Use rarely — only for known benign issues.
💡

Common Pattern: Redirect error rows → add a Derived Column to capture the error description → write to an error staging table for investigation.

Checkpoints

SSIS can save package state to a checkpoint file. If the package fails, the next run resumes from the last failed task.

-- Checkpoint properties (set on Package)
CheckpointFileName = "C:\Checkpoints\MyPackage.chk"
CheckpointUsage    = IfExists
SaveCheckpoints    = True

Deployment & SSIS Catalog

⏱ 5 min📌 Module 10🎓 Advanced

Project Deployment Model

The recommended deployment approach. Build your project into an .ispac file and deploy it to the SSIS Catalog (SSISDB).

Deployment Steps

1. Build Project

In Visual Studio: Build → Build Solution. Produces an .ispac file in the bin/Development folder.

2. Deploy to Catalog

Right-click project → Deploy. Choose target SQL Server and folder in the SSIS Catalog. Or use ISDeploymentWizard.exe.

3. Configure Environments

Create environments (Dev, QA, Prod) in the catalog. Map environment variables to project/package parameters.

4. Schedule with SQL Agent

Create a SQL Agent Job → New Step → Type: SSIS Package → Select from catalog. Set schedule and notifications.

SSISDB Catalog Structure

SSISDB
  └── Folders
       └── Projects
            └── Packages
       └── Environments
            └── Environment Variables

Useful Catalog Queries

-- Recent executions
SELECT execution_id, folder_name, project_name,
       package_name, status, start_time, end_time
FROM catalog.executions
ORDER BY start_time DESC;

-- Error messages from last failed run
SELECT message_time, message
FROM catalog.event_messages
WHERE operation_id = 12345
  AND event_name = 'OnError';

Performance Tuning

⏱ 5 min📌 Module 11🎓 Advanced

Top Optimization Strategies

#StrategyImpact
1Use SQL query at source (filter, sort, join in SQL — not SSIS)🔴 High
2Prefer OLE DB Destination with "Table or View — Fast Load"🔴 High
3Use Full Cache mode on Lookup transforms🔴 High
4Avoid Sort transform — ORDER BY in source SQL🟡 Medium
5Tune buffer sizes (DefaultBufferMaxRows, DefaultBufferSize)🟡 Medium
6Drop indexes before bulk load, rebuild after🟡 Medium
7Use staging tables + MERGE instead of row-by-row🔴 High
8Enable parallel execution (MaxConcurrentExecutables)🟡 Medium

Buffer Tuning

-- Data Flow Task properties
DefaultBufferMaxRows = 100000    -- rows per buffer (default: 10000)
DefaultBufferSize    = 104857600 -- 100 MB max (default: 10 MB)
EngineThreads        = 10        -- parallel threads (default: 10)

Lookup Cache Modes

Full Cache

Loads entire reference table into memory before pipeline starts. Fastest for repeated lookups. Default and recommended.

Partial Cache

Caches rows as they're looked up. Good when reference table is too large for memory but most lookups hit a subset.

No Cache

Queries the database for every row. Very slow — avoid unless the reference data changes during execution.
